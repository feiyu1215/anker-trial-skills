答题的本质就一句话：每一轮你的输入都应该是「判断 + 指令 + 约束」，而不是「一个问题」。 循环是：你下判断 → AI 出草稿 → 你审并修正。谁先给判断，谁就是思考的主角——这句话决定了评委在录屏里看到的是你还是 AI。

0 · 开局：读题四问 + 先验 AI

看材料之前的两个动作。材料原话："先了解关键术语是什么 → 业务流程是什么 → 问题到底出在哪里 → 最后到底要解决什么。"

读题四条自问（按这个顺序，别跳）
先问要落到什么程度
关键术语是什么题干里每个专有名词，你能不能用一句自己的话解释？解释不了的标出来——那正是要先让 AI 给你补的课，也是你后面判断它对错的抓手
业务流程是什么钱 / 物 / 信息从谁流向谁、经过哪几步？画不出来就说明你还没懂这题的业务，此时问 AI 等于被它牵着走
问题到底是出在哪先自己给一个位置判断（哪一环、哪类对象），再去和 AI 的比——有你的一版才有"差异"可看
最后到底要解决什么落到"支持谁做什么决策"。这决定了交付物的骨架，也决定了哪些材料是干扰项
验伪秒回要警惕：先确认 AI 在你要的状态里
材料里的真实翻车现场
  • 有人发完消息 AI 秒回答案，他觉得不对劲，问了一句"你是谁？"——才发现根本没进设定的角色和上下文
  • 教训：太快、太顺、太通用的回答，先怀疑它没吃到你的材料和约束。材料原话："很考验提示词功底，最好检查一下模型输出的答案是否合理，避免被带偏"
开局验伪
在开始之前，先确认你的状态，逐条回答：
1）你现在扮演的角色是什么？
2）你已经读取了哪些材料、路径分别是什么？逐份列出你读到的核心事实（用你的话概括，不要复述原文）；
3）我给你的约束里，你记住了哪几条？

如果你其实没读到材料，直接说"没读到"，不要凭常识作答。

A · 答案本身长什么样（ISR 三段）

官方方法论是 Insight（洞察）→ Strategy（策略）→ Operation（执行）。你的交付物就按这三段组织，内容用 M1–M10 体检表逐格填。

段官方要什么必产出（缺一不可）最易漏
Insight 对原始材料做数据/文本分析，输出洞察结论 问题判断 · 证据链 · 用户与场景分层 · 漏斗诊断 · 根因链 只做数据罗列不结论；根因写成现象（"活跃度低"是现象不是根因）；反馈不挂漏斗环节
Strategy 据洞察梳理策略：目标画像、核心动作、风险点 候选方案（≥2，含不采纳理由）· 优先级与取舍 · 可执行动作六要素 方案不映射回根因；只给一个方案；动作停在"适当提醒"这种空泛词
Operation 把策略转化成可交付结果 验证指标（核心/过程/护栏）· 上线与灰度节奏 · 风险控制 · 交付目录 / Demo 漏护栏指标（最多人漏）；只有成功线没有失败线和回滚线；Demo 引 CDN 白屏
时间账（3h 主表）：学习 20 分钟 + 提交 15 分钟是硬成本，剩 145 分钟解题。其中 Insight 侧四个动作（交叉 11 / 补盲 10 / 填 Insight 27 / 压测 10）合计 58 分钟、占四成——评委判断思考深度的地方，别省；Strategy 19 分钟、Operation 18 分钟；质疑轮预留 7 分钟（触发式，但 AI 编数据/套常识几乎必然至少触发一次）；其余：定向 6、框架 13、校验 10（含 5 分钟回补指标表）、整合 6、Demo 7，合计 144，留 1 分钟缓冲。 不要一上来就写方案——洞察没立住，后面全白搭。
⚠️ 填 Insight 的 27 分钟是三次交互，不是一轮（5a 问题判断 9／5b 分层漏斗 9／5c 根因链 9）——每块都要它复述、你确认，再进下一块。按"一轮"的节奏赶，最容易被砍掉的就是 Insight 的深度。

B · 完整交互回合表（14 轮）

这是"我和 AI 到底要做哪些交互"的答案。轮数是自然结果，不是目标——该有的 14 步走到就有十几轮， 不要为了凑轮数硬聊，也不要为了省轮数跳步。第 8 轮（质疑）是触发式的，命中条件才走，可能走 0 次也可能走 3 次。
时间按校招 3h 主表标（累计分钟）：学习 20 分钟 + 提交 15 分钟是硬成本，别按 180 分钟满打满算。2h 场景按《完整打法》③压缩表同比例压，Demo 用 10 分钟极简版。

关于"要聊多少轮"
  • 有人说"至少 30 轮"——那和"云桌面卡、上下文变长后 AI 变慢、总共才 3 小时"直接冲突，不作为指标
  • 真正该数的不是轮数，是你留下了多少条"属于自己的判断 + 被修正过的错误"。这些才是录屏里的证据
  • 为凑轮数去质疑 = 纯浪费，评委一眼看穿

C · Prompt 全集（可直接复制）

按轮次排列。方括号 ［…］ 是要你现场填的占位——每道题的业务领域、指标、角色都不同，不要套死。

P0轮 0 · 全局约束（一次定死）
P0
接下来所有工作都遵守以下规则，后续每轮默认生效，我不再重复：

1）角色：你是［按本题领域填：资深XX专家，XX年经验，擅长在复杂约束下做XX］。
2）路径：所有输入和输出文件都放在 ［文件夹绝对路径］，每次生成告诉我完整保存路径。
3）禁编造：所有数据、结论必须标注来源；禁止编造业务数据，没有的一律写"数据不足"并说明补什么。
4）禁模糊：不准出现"适当""优化""显著提升""确保顺利"这类词，要给可量化或可判定的标准。
5）不迎合：我的判断和你的不一致时，先指出我错在哪并给证据，不要迎合我。
6）分块：每次只完成我指定的一块，做完先复述这块结论，我确认后再进入下一块。
分块必须互斥（各块不重叠、合起来能覆盖这道题），你先用 MECE 自查一遍再开做。
7）纠错：我指出某处出错时，只改那一部分，不要整份重来。
P1轮 1 · 定向：读材料 + 拆交付 + 排时间
P1
【输入】全部题目材料（［路径/粘贴］）；总时限 ［3小时/2小时］；我的一句话理解：［你自己的一句话理解］。
【任务】
1）列出题目最终要求交付什么：共几项、分别什么格式、什么命名、有没有字数或结构要求；
2）按总时限排一张时间分配表：每一步干什么、各几分钟、留多少时间提交；
3）校验我上面的理解：直接指出哪里偏了、漏了什么关键约束，不要先夸我。
【约束】先别做业务分析，本轮只做这三件事；一切以题目原文为准，不要脑补要求。
【输出】交付清单 + 时间分配表 + 对我理解的纠错清单。
【边界】本轮不分析问题、不搭框架。
P2轮 2 · 要框架（先骨架，不要方案）
P2
【输入】轮 1 确认的交付要求；我的拆法初判：［你认为该按什么主线拆、为什么］。
【任务】
1）按 Insight → Strategy → Operation 三段给我这份交付物的框架骨架：分哪几个板块、每块放什么、大概占多少篇幅；
2）先评价我的拆法有没有漏洞，再给我你的版本。
【约束】用列表给我；各块互斥、合起来覆盖全部交付要求（MECE 自查后再给）；现在不要生成具体方案。
【输出】框架骨架清单 + 对我拆法的指正。
【边界】框架确认前不写任何正文内容。
P3轮 3 · 材料交叉（矛盾 / 干扰 / 缺失）
P3
【输入】［N］ 份材料（［路径/粘贴］）。
【任务】交叉对比，分三张清单给我：
1）矛盾：哪些信息之间对不上？可能谁错了、依据是什么；
2）干扰项：哪些看起来重要、但对本题决策其实无用？为什么；
3）缺失：缺了哪些关键信息？缺了它会影响哪个判断？能不能用现有材料或其他方式补。
【约束】不要只复述；每一条都给依据（指向哪份材料哪一段）。
【输出】矛盾 / 干扰项 / 缺失 三张清单。
【边界】本轮不下结论、不做方案。

追问（体现"纠错迭代"）："你识别得对。但我要追问一层：［某方案］除了［表面缺点］，还有没有更深的问题？我担心 ［你的隐忧］ 本身可能不成立。"

P4轮 4 · 外部补盲（打破信息孤岛）
P4
【输入】本题背景与我们已有的交叉结果（见前文）。
【任务】用搜索功能补充三类外部基准，并并入分析：
1）［本题领域的主流解法 / 通行框架］；
2）［可对比的公开数据或行业区间］；
3）［同类公司在类似阶段踩过的坑］。
【约束】补完必须说清每个基准和我们哪里可比、哪里不可比，不要直接套；每条标注来源。
【输出】外部基准清单 + 可比性判断 + 并入后的分析更新。
【边界】只补参照系，不推翻已确认的事实结论。
P4-降级（云桌面无网时，用这条替代，不要跳过）
【输入】本题背景与我们已有的交叉结果（见前文）。当前环境无法联网。
【任务】不要空过这一轮，改为：
1）列出本题应该补哪三类外部基准，每类说明"为什么它对这道题重要、缺了它会影响哪个判断"；
2）基于你的通识，对每类给出方向性判断（如"这个行业的该指标通常在什么量级、主流解法有哪几派"），
   并明确标注为"常识推断，未经验证"；
3）指出哪几条结论因为缺外部基准而置信度下调。
【约束】禁止给出具体数字充当行业基准——记不清来源的行业数字比"没有"更危险，评委一问就塌。
【输出】应补基准清单 + 方向性判断（标常识推断）+ 置信度下调声明。
为什么要有这条降级分支：有网时 P4 价值很大（演练中搜到"首周完成一次有意义动作的用户留存近 3 倍"， 直接支撑了核心判断）；但云桌面可能没网，此时硬凑一个记不清来源的行业数字，是比"没有参照系"严重得多的问题—— 它会被写进交付物，然后被追问来源。
P5轮 5 · 填 Insight（分块填，别一次要完）
P5-a 问题判断与证据链
【输入】题干 + 轮 3 交叉结果 + 轮 4 外部基准。
【任务】填 Insight 第一块：问题判断与证据链。
1）把"XX 低 / XX 差"这种模糊说法，改写成"在［范围/周期/场景］，［对象］出现［可观察差距］，相对［基线］影响［结果］"；
2）建证据链：把信息三分为【已验证事实 / 用户主观反馈 / 待验证假设】；
3）指出至少 1 条数据与反馈之间的张力。
【约束】每条结论标来源，【数据】/【反馈】/【推导】三选一；说不清来源的标"数据不足"并写明补什么。
【输出】问题判断段 + 证据链表 + 张力至少 1 条。
【边界】只填这一块，做完先复述结论，我确认后再进下一块。
P5-b 分层 + 漏斗
【输入】题干漏斗数据（如有）+ 用户反馈 + 上一步的问题判断。
【任务】填 Insight 第二块：分层 + 漏斗诊断。
1）用户/对象分层：维度由本题定（生命周期/行为/价值/来源等，你建议并说理由），每层给定义、判定规则、样本量、主要障碍；
2）场景分层：拆 2–3 个，每个写全 触发原因 + 目标任务 + 前置状态 + 时间压力 + 环境 + 成功标准；
3）漏斗诊断：环节按真实路径定，每环给转化率、流失率、绝对流失量；并把分层回挂——指出哪类人在哪类场景的哪一环掉得最狠。
【约束】断点判据用双条件：绝对流失量大 且 相对转化率低，两条同时满足才算；无直接指标的环节用代理指标并标注"代理指标"；没有数据的环节标"数据不足"，不要用估算充数。
【输出】分层表 + 场景表 + 分层漏斗差异表 + Top 2–3 断点。
【边界】不做根因推导，那是下一块。
P5-c 根因链（最关键）
【输入】漏斗断点 + 分层差异 + 交叉结果。
【任务】填 Insight 第三块：根因机制——这是整份答案的核心。
1）至少 3 条根因链，每条写全四段：现象（哪类人·哪一环·什么表现）→ 机制（为什么这环会断、为什么这类人更敏感）→ 原因（底层触发因素）→ 结果（对核心结果的具体影响）；
2）至少 1 条跨环节联动（不是单点失效，是环节之间配合断了）；
3）至少 1 条不是从材料里直接抄的独立判断——由数据 + 反馈 + 分层交叉推出的新洞察。
【约束】每条标证据来源；主动列竞争解释（还有什么别的可能、为什么排除）；区分"已验证根因 / 待验证假设"，别混着写；禁止把现象重命名当原因（"活跃度低""用户没感知"都不是根因）。
【输出】按影响与证据排序的根因清单。
【边界】不做方案，方案在 Strategy 段。
P6轮 6 · 压力测试（你给判断，让它反驳）
P6
【输入】我的关键判断：本题最关键的根因是［你的判断］，理由是［具体依据，指向材料哪一段/哪个数据］。
【任务】你做对手，从三个角度反驳我：
1）这个判断如果错了，最可能错在哪；
2）材料里有没有能证伪它的证据；
3）哪条竞争解释比它更能解释全部现象。
【约束】不要说"也有可能存在其他因素"这种空话——要拿出具体证据或具体推理；如果你反驳不倒我，明确说"我反驳不倒，理由是……"，不要为了显得中立而和稀泥。
【输出】逐条反驳，或明确承认反驳不倒。
【边界】只压测这个判断，不引入全新方向。
【收尾——这步别漏】反驳成立的，立即回写进根因清单：改排序、改状态（已验证 ↔ 待验证）、补证据标注（如"该反证存在选择偏差"）。
不要只在对话里口头修正——交付物里留着未修正的根因，等于这轮白做。
P7轮 7 · 填 Strategy（方案 → 取舍 → 动作）
P7
【输入】已确认的根因清单 + 收益/风险边界 + 资源约束。
【任务】填 Strategy：
1）围绕根因发散 2–3 个有实质差异的方向，每个说清：对应哪类人、挂哪条根因（标编号）、修复哪个环节或跨环节断点、预期收益、成本与依赖、主要风险、适用条件；给 ROI 量级预估即可，不编精确财务数；
2）用 ICE 或 RICE 排序，说清比较周期和单位；
3）主动列 1–2 个不采纳的方向及理由，理由挂回根因/漏斗/分层的证据；
4）收敛到 1–2 项写成可执行动作，六要素一项都不能少：目标用户 / 触发场景 / 展示内容或交互方式 / 频次·节奏·阈值 / 与现有体系的关系 / 成功判定方式；涉及提醒·引导·触达的，必给触发条件 + 频次上限 + 观察周期；
5）明确写"不做什么"，以及选了 A 就放弃了什么；
6）方案覆盖面自查：竞品对标 / 商业化 / 设计 / 多版本迭代路径 / 质量保障 五个侧面逐一过一遍，不适用的明确写"本题不适用"，不要默认跳过。
【约束】方案必须映射回根因，禁止写成"多发券 / 降价 / 一刀切活动"；禁止"适当 / 优化"类模糊词。
排序工具（ICE / RICE）可以覆盖——它的 Impact 是线性打分，表达不了"改变顺序/改变结构"这类非线性效应；
但覆盖必须在正文写明理由，而这个理由本身就是评分点。
【输出】候选方案对比表 + 优先级决策（若覆盖排序，附覆盖理由）+ 可执行动作（六要素）+ 不做什么。
【边界】不做灰度与指标体系，那是 Operation 段。
P8轮 8 · 质疑（触发才用，模板）

触发条件见《打法》第 ⑧ 步。模板要点：指出它哪个具体判断错了 + 证据 + 你认为对的 + 要求重答。

P8
【输入】你刚才的结论：［复述它的具体结论］。
【我的质疑——三件套】
1）错在哪：［具体错在哪 + 证据来自哪份材料哪一段］；
2）后果：按你这个做法会导致［后果］；
3）我的版本：［我的判断］，因为［理由］。
【要求】在 ［我指出的前提/约束］ 下重新回答；只改这一部分，其他已确认的内容保持不变。
【输出】修正后的该部分结论。
P9轮 9 · 填 Operation（指标 / 节奏 / 风险）
P9
【输入】已确认的优先方案与动作规则 + 漏斗环节 + 风险红线。
【任务】填 Operation：让方案可验证、可回滚。
1）三类指标：核心结果 / 过程机制 / 护栏（护栏 = 不可接受的副作用，具体指标你按本题建议，但这一项不能省）；
2）三条线：成功线 / 失败线 / 回滚线，每条都要给具体数字或相对变化；
3）每个阈值配四件套：数值 + 观察窗口 + 比较方式/对照组 + 判定时点；
4）灰度节奏：维度（用户/地域/流量比例）+ 分批节奏，并说明"这批是谁的百分之几、为什么够支持判断"；
5）验证设计与显著性处理；
6）回滚预案：触发什么条件切回、怎么切、切回后已产生的数据/结果怎么处理；
7）风险清单：逐条写"风险 + 谁受影响 + 怎么监测 + 触发后怎么办"。
【约束】阈值没有依据就写"待定 + 确定方法 + 责任人 + 补齐时间"，不要编数字；安全止损不必等效果检验显著。
【输出】验证方案 + 完整阈值表 + 回滚预案。
【边界】不重新分析根因、不新增候选方案。
P10轮 10 · 换角色校验 + 消灭模糊词
P10-a 换角色审
【输入】我们的完整方案（见前文）。
【任务】以 ［选一个最刁的角色：CFO / 业务方负责人 / 一线执行人 / 合规］ 的视角审这份方案，核心一问："你这个方案凭什么 ［值这个投入 / 能被信任 / 真能落地］？"
【要求】以该角色逐条挑毛病，然后把验收标准改写成可量化、可验收、不留模糊的指标。
【输出】该角色视角的问题清单 + 逐条改写后的验收标准。
P10-b 虚词清零
【输入】我这份交付物全文。
【任务】挑出所有无法验收的表述，逐条给可验收的改写版本。
【约束】重点排查这类词：适当、合理、优化、提升、加强、确保、持续、尽快、显著、大幅；每条改写必须能被第三方判定"做到还是没做到"；改不了的，直接标"此处无法验收"，我来决定是补证据还是砍掉这句话。
【输出】"模糊表述 → 可验收改写"对照表。
P11轮 11 · 整合成交付物
P11
【输入】前面各轮已确认的全部内容。
【任务】整合成完整交付物：
1）结构按题目要求的格式和命名；
2）只能使用我们已经确认过的结论和数据，不得新增任何未经讨论的内容；
3）凡是来源为"推导"或"数据不足"的地方，保留标注，不要悄悄写成事实；
4）附一节「这套方法下次怎么复用」：把本次的判断框架、指标口径、验证套路沉淀成可复用的东西；
5）附一小节「人机分工」：哪些判断是我下的、哪些执行交给 AI——直接回应"驾驭 AI 提升产出"这条考察点。
【输出】完整交付物，保存到 ［路径］，完成后告诉我完整路径和文件清单。
【边界】整合时发现前后矛盾的，先停下来问我，不要自行取舍。
P12轮 12 · Demo 生成（无网硬约束）
P12-a 先要大纲
【全局约束】接下来所有网页工作遵守：生成纯静态单页 HTML，不依赖任何外网 CDN、外部字体或 JS 库（云桌面可能没网）；双击浏览器能打开；中文 utf-8 不乱码；浅色主题、信息密度高；图表用纯 CSS 或内联 SVG 手写，不要引 Chart.js / ECharts；不要生成需要 npm install 或构建的项目。
【输入】我们确认的分析结论（读取 ［分析文件路径］）。
【任务】先给我 Demo 结构大纲：顶部一句话核心结论、然后分哪些板块、每块放什么。现在不要写代码。
P12-b 生成 + 自检

【自检，生成后逐条确认】① 有没有外链资源（有就内联化或删掉）；② 中文编码对不对；③ file:// 直接打开能不能正常显示；④ 有没有我们没分析过的编造数据。
【输出】修完问题后告诉我文件保存的完整路径。

P13

D · 范例与对照

下面都是"形状示范"，括号里的内容要按当题业务替换——别照抄数字和场景。

例 1交互话术：点菜员 vs 主角
❌ 把判断权交出去✔️ 你是主角
"AI，你觉得这个项目先做哪一步？""我的判断是先做 A 再做 B，因为 A 卡着 B 的交付，B 做早了也白做。你帮我验证这个顺序有没有漏洞。"
"帮我分析一下这批材料。""我读完材料的初步判断是 ［一句话］。你按这个方向深挖，并指出我哪里理解错了。"
"请你说一下项目的关键是什么，并给我建议。""我认为关键是 ［具体那一件事］，因为 ［具体理由/教训］。你反驳我，或告诉我更该先解决什么。"
"还有其他可能吗？""如果这个判断错了，最可能错在哪？材料里有没有能证伪它的证据？拿不出证据就直说反驳不倒。"
例 2质疑：空泛 vs 三件套
❌ 空泛（比不质疑还糟）
  • "你这样做不太对吧？"
  • "你有没有抓住关键？"
  • "我觉得这个方案还不够好。"
  • → 姿态很足、内容为零，一眼看穿你没想清楚
✔️ 三件套 = 错在哪 + 证据 + 我的版本
  • 错在哪："你判断 X 方案可行，但你没把 ［某部门休假/某依赖延期］ 算进去"
  • 证据："材料第 3 页写明 ［依据］，按你这张表会延期 ［N］ 天"
  • 我的版本："我建议把 A 和 B 对调，先解决 ［X］"
例 3模糊词 → 可验收改写（"求极致"的主战场）
模糊说法为什么验收不了可验收改写
确保进度顺利什么叫顺利？谁判定？第 3 周完成 80% 的测试用例，通过率 ≥ 95%
适当提醒用户没触发条件、没频次、没上限用户在［环节］停留 > 30s 且无有效操作时提示 1 次；同一用户 24h 内最多 1 次
提升用户满意度没测量方式、没样本要求任务完成后 7 日内满意度评分 ≥ 4.2，且有效样本 ≥ 200
优化推荐效果没方向、没判据推荐点击率相对提升 ≥ 5%，且 95% 置信区间下界 > 0
加强风险控制空泛，无法判断是否做到异常订单拦截率 ≥ 99%，误拦截率 ≤ 0.5%，超阈值自动熔断并告警到［责任人］
持续迭代优化没节奏、没停止条件每两周复盘一次，按［指标］决定继续 / 调整 / 停止，连续 2 个周期无改善即停止投入
降低运营成本没口径、没基线单次任务人工处理时长下降 ≥ 20%（对比改动前 4 周同口径均值）
例 4根因链四段（结构示范，内容按题替换）
根因链示范
现象：在［场景/周期］，［某类用户］在［某环节］的完成率明显低于其他群体，且近［周期］持续走低。
       （这是可观察事实，不是原因）

机制：该环节要求用户自行理解并操作［X］；这类用户缺少［某前置认知/准备］，
       因此在这一环的判断成本远高于其他群体；一旦首次失败，系统又没有给出
       可理解的失败原因和可恢复路径，用户就直接放弃而不是重试。
       （为什么这环会断、为什么这类人更敏感）

原因：底层是"状态与反馈不可见"——系统没有把当前进展、失败原因、下一步
       明确暴露给用户，用户只能靠猜。
       （底层触发因素，不是现象的重命名）

结果：该环节流失占整体流失的［比例］，直接压低［核心结果］；
       且首次失败的用户后续复用概率显著更低，影响是长期的。

证据：【数据】［某报表/口径］；【反馈】［原话/工单，N 条］；【推导】［推断依据］
竞争解释：也可能是［另一种解释］，排除依据是［为什么排除］。
状态：已验证根因 / 待验证假设（二选一，不要含糊）
例 5动作六要素（结构示范）
动作六要素示范
目标用户：［某分层］用户，且处于［某场景］
触发场景：进入［某环节］后 30s 内无任何有效操作
展示内容/交互：在当前页面内给出"当前状态 + 下一步 + 一键继续"的轻量提示条，不跳出、不遮挡
频次·节奏·阈值：同一用户同一环节 24h 内最多 1 次；同一次会话最多 2 次；与［现有功能］冲突时不展示
与现有体系关系：复用现有［组件/埋点/权限］，不新增独立入口
成功判定方式：该环节完成率相对提升 ≥［X］，且被提示用户的投诉率、退出率不升高（护栏）

Plan B：若上线后 7 天内该环节完成率提升 <［X］，或投诉率上升 >［Y］，
          则关闭该提示，回退到［原方案］，并转向验证［备选机制］。
不做什么：不做全量弹窗、不做跨渠道推送、不靠补贴拉动。

E · 各段要点与易错

Insight最容易"看起来很满、其实很空"的一段
要点
  • 每个结论后面必须能追到【数据】/【反馈】/【推导】之一
  • 根因一定要有"机制"层，跳了这层推导链就断了
  • 至少留一条"不是抄材料、是你推出来的"判断——这是区分度
  • 反馈必须挂到漏斗环节上，否则就是无法对照的噪音
  • 交叉验证后要回头修正初判，别一路走到黑
易错
  • 把现象当根因（"活跃度低""用户没感知"都不是根因）
  • 只看转化率不看绝对流失量（小环节改了白改）
  • 分层完不回挂漏斗 = 自嗨
  • 样本比例直接外推成总体比例
  • 不标证据来源 → 评委无法倒查
Strategy最能体现"取舍"的一段
要点
  • 方案必须挂回根因编号，评委一定会倒推
  • ≥2 个方向才有取舍，只有 1 个 = 没比较
  • 写清"不做什么"和"选了 A 放弃了什么"
  • 动作六要素一项不能少
  • 触达类必给触发条件 + 频次上限 + 观察周期
易错
  • 偷懒写成"多发券 / 降价 / 一刀切活动"
  • 不做 ROI 预估，显得没算过账
  • 只说好处不说代价（显得没做过权衡）
  • "适当提醒""持续优化"——一出现执行性归零
Operation最见落地感的一段
要点
  • 三类指标：核心结果 / 过程机制 / 护栏
  • 三条线：成功 / 失败 / 回滚，都要有数字
  • 阈值四件套：数值 + 观察窗口 + 对照组 + 判定时点
  • 回滚预案要写清切回后已有数据/结果怎么办
  • 阈值没依据就写"待定 + 确定方法 + 责任人 + 时间"
易错
  • 漏护栏指标（最多人漏的一项）
  • 只有成功线没有失败线和回滚线（那叫许愿不叫验证）
  • 不做显著性处理，被随机波动骗
  • 灰度不设对照组
  • Demo 引 CDN → 无网白屏（头号死法）
最后提醒：Prompt 是脚手架不是答案。所有方括号都要你现场填——填进去的那个判断，才是你真正在被评分的东西。 AI 能帮你读材料、整理信息、算数据、生成方案，但最后决定这份东西能不能交的，还是你自己的判断：逻辑对不对？数据准不准？方案到底能不能落地？
