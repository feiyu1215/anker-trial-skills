# 开局检查单（参考／检查单）

> 铁律：本 skill 只提醒你"开考第一步该做什么、环境先验什么"，不替你做、不替你写指令。

## ① 官方教学别跳过（0–20 min，倒计时内）
- 教学材料就是<b>评分标准的预告</b>——评委在看什么、什么叫好答案，里面都演了。
- 读的时候同步跑读题四问（轮1 调 `anker-read-problem`），读完直接进定向。

## ② 环境验证（能点的都点一遍）
- 能不能联网（<b>结论要落到 P4 的分支选择上</b>）：有网 → 正常走外部补盲；
  <b>无网 → 走手册里的 P4-降级</b>，改为让 AI 列出"应补哪三类基准、各自为什么重要"，并在交付物标注"本轮无外部基准可补"。
  <b>绝不用记不清来源的行业数字充数</b>——那比没有参照系更危险；
- 中文输入法好不好用（影响你打指令的速度）；
- VS Code + 终端 + Claude Code 都能开；
- `/run` `/export` `/rewind`、sub-agent / 多窗口并行是否可用（不可用就别把"会带人"写进策略）；
- 随手生成一个小 html 用 file:// 打开，确认编码正常。

## ③ 工程纪律（做完再开始答题）
- 先翻到题目<b>最底下看最终交付什么</b>——知道终点才知道框架长什么样；
- 按题目要求<b>建好文件夹并完成命名分类</b>，背景材料、原始数据都丢进去；
- 对 AI 的第一句话就声明：<b>所有输入和输出都放这个路径</b>，每次生成文件报告完整路径；
- 时间表让 AI 排（轮1 完整指令见手册 P1）。

## ④ 全程纪律一句话
- 边做边输出，绝不最后统一生成；离截止 15 分钟必须进入提交窗口。
- <b>质疑轮虽是触发式，但至少会触发一次</b>（AI 编数据 / 套常识 / 漏约束），时间表已为它留 5–8 分钟——别把这段时间挪作他用。
- <b>填 Insight 是三次交互</b>（问题判断 / 分层漏斗 / 根因链），不是一次问完。
- <b>上下文变长或需换会话时</b>，先让 AI 更新工作状态文件再继续（指令见手册附录 B-②），不重头开始。
